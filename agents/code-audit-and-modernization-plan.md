# План аудита кода и обновления библиотек

## Исходное состояние

Проект использует Create React App с CRACO. Основные зависимости на момент составления плана:

- React 18.2;
- TypeScript 4.9;
- Mantine 7.6;
- React Router 6.22;
- react-scripts 5.0.1;
- Testing Library и Jest через инструментарий Create React App.

Обновления не следует выполнять одной массовой командой. Сначала необходимо восстановить и проверить запуск текущей версии, затем обновлять зависимости небольшими независимыми этапами.

## 1. Зафиксировать исходное состояние

- Проверить версии Node.js и npm, состояние Git и `package-lock.json`.
- Выполнить чистую установку зависимостей через `npm ci`.
- Запустить сборку, тесты и dev-сервер.
- Зафиксировать ошибки отдельно по категориям: установка, компиляция TypeScript, сборка, тесты и поведение в браузере.

## 2. Провести аудит кода

- Проверить маршрутизацию, контекст активной игры и страницы создания, сохранения, восстановления и результатов.
- Найти устаревшие API, неявные `any`, небезопасные приведения типов, проблемы эффектов и состояния.
- Проверить граничные случаи игровой логики и вспомогательные функции.
- Оценить существующие тесты и определить пользовательские сценарии, не защищённые от регрессий.

## 3. Составить карту зависимостей

- Получить актуальные версии через `npm outdated`, проверить дерево зависимостей через `npm ls` и уязвимости через `npm audit`.
- Разделить прямые зависимости и транзитивные проблемы из `react-scripts`.
- Для каждой библиотеки зафиксировать текущую версию, актуальную стабильную версию, совместимость с выбранной Node.js LTS, критические изменения и объём необходимых доработок.
- Не применять массово `npm audit fix --force`.

## 4. Обновлять зависимости небольшими этапами

- Сначала установить совместимые patch- и minor-обновления.
- Затем обновить TypeScript и типы, исправив ошибки компиляции.
- Отдельно обновить React, Mantine, React Router и Testing Library, следуя руководствам по миграции.
- После каждого этапа повторять сборку, тесты и ручную проверку основных сценариев.

## 5. Решить судьбу CRA и CRACO

Предпочтительный вариант — рассмотреть миграцию на Vite: `react-scripts` сохраняет устаревшее окружение, а CRACO в проекте преимущественно используется для алиасов, которые Vite поддерживает напрямую.

Миграцию следует выполнять отдельным этапом, не совмещая её с одновременным обновлением всех UI-библиотек. Альтернатива — временно оставить CRA, если приоритетом являются минимальные изменения.

## 6. Проверить результат end-to-end

- Создание новой игры, ввод очков и просмотр результатов.
- Сохранение и восстановление игры.
- Навигация и страница 404.
- Production-сборка и запуск собранного приложения.
- Отсутствие ошибок в консоли.
- Корректная работа светлой и тёмной темы и основных размеров экрана.

### Миграция на TypeScript 7 — выполнена

Оценка: TypeScript 7.0 не предоставляет программный API, поэтому typescript-eslint напрямую с ним несовместим (peer-диапазон `typescript-eslint@8.72.1` — `>=4.8.4 <6.1.0`). Официальная рекомендация Microsoft — side-by-side установка через npm-алиасы, которая и применена:

- `typescript` → `npm:@typescript/typescript6@^6.0.2` — TS 6 с API для typescript-eslint, бинарь `tsc6`;
- `@typescript/native` → `npm:typescript@^7.0.2` — нативный TS 7, бинарь `tsc` (используется в `npm run build` и `npx tsc --noEmit`).

Подготовка `tsconfig.json` (проверена сначала на TS 5.9):

- Удалён `baseUrl`, который в TS 7 запрещён; `paths` переписаны относительно корня проекта.
- В `paths` добавлены маппинги `routing` (баре-импорт к `src/routing/index.ts`) и `types/*`, которые раньше резолвились неявно через `baseUrl`.
- Добавлено `types: ["node"]`, так как в TS 7 глобальные типы по умолчанию не подключаются; тесты импортируют из `vitest` явно.

Проверки после миграции: `tsc --noEmit` (TS 7.0.2), `eslint .`, `npm test` (32 теста), `npm run build`, production-аудит (0 уязвимостей) — все пройдены. Время `tsc --noEmit` сократилось примерно с 4,9 c до 1,7 c.

Миграция закоммичена коммитом `5c75549` (feat: migrate to TypeScript 7 with TypeScript 6 side-by-side).
