# Карта зависимостей для пункта 4

Документ фиксирует результаты пункта 3 общего плана: установленные версии, доступные обновления, требования совместимости и рекомендуемый порядок миграции. Во время аудита зависимости не изменялись.

## Окружение

- Текущая версия Node.js: `20.11.1`.
- Текущая версия npm: `10.2.4`.
- Актуальная Node.js LTS на момент аудита: `26.13.0`.
- Целевое окружение для модернизации: Node.js 26 LTS, Vite 8 и Vitest 5.

Ограничения современного инструментария:

| Пакет | Версия | Требования |
|---|---:|---|
| `vite` | 8.3.5 | Node.js `20.19+` или `22.12+` |
| `@vitejs/plugin-react` | 6.1.2 | Node.js `20.19+` или `22.12+` |
| `vitest` | 5.0.5 | Node.js `22.12+`, `24+` или `26+` |
| `@testing-library/jest-dom` | 7.0.1 | Node.js `22+` |

Текущая Node.js `20.11.1` недостаточна для этой связки.

## Уязвимости

`npm audit` на момент аудита показывает 82 уязвимости:

- 22 low;
- 20 moderate;
- 36 high;
- 4 critical.

Все четыре critical ведут через `react-scripts`: Jest/`form-data`, dev-server/`proxy-addr`, `shell-quote` и `websocket-driver`. Они преимущественно относятся к инструментарию разработки, а не к игровому браузерному коду.

Прямые проблемы безопасности:

- `react-router-dom@6.22.3` — high, обновить до 6.30.6 перед миграцией на v7;
- `postcss@8.4.35` — high, обновить до 8.5.32;
- `react-scripts` и связанное дерево — устраняются полноценно удалением CRA/CRACO.

`npm audit fix --force` не применять: npm предлагает downgrade `@craco/craco` до 5.9.0 и установку `react-scripts@0.0.0`.

## Рекомендуемый порядок обновлений

1. Обновить `react-router-dom` до 6.30.6 и `postcss` до 8.5.32.
2. Выполнить остальные совместимые обновления, включая React 18.3 и типы 18.3.
3. Удалить неиспользуемый `web-vitals` и исправить распределение пакетов между `dependencies` и `devDependencies`.
4. Перейти на Node.js 26 LTS и Vite/Vitest, удалив CRA и CRACO.
5. Обновить TypeScript до 5.9.3 и тестовые библиотеки.
6. Перейти на React 19.3 и соответствующие типы.
7. Обновить React Router до 7.
8. Последовательно выполнить миграцию Mantine 7 → 8 → 9.
9. Рассмотреть TypeScript 7 отдельно после стабилизации остального окружения.

После каждого этапа необходимо запускать проверку TypeScript, ESLint, production-сборку, тесты и ручную проверку основных пользовательских сценариев.
